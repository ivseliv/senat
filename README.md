# Решения Общего собрания Правительствующего Сената, 1866–1915

Статический сайт-архив (в духе Old Bailey Online) по OCR-текстам печатных изданий решений
Общего собрания кассационных и с участием I и II департаментов Правительствующего Сената.

## Состав
- `index.html` — весь интерфейс (без сборки и зависимостей, шрифты с Google Fonts).
- `data/index.json` — метаданные 1212 решений: № по изданию, дата, рубрика (заголовок),
  участники заседания, пометы автоматической обработки, нормализованная рубрика для поиска.
- `data/src/*.json` — полные тексты решений, по одному файлу на исходный том
  (подгружаются по требованию при открытии решения).

## Как получены данные
Docx (ABBYY-OCR печатных томов) → pandoc → сегментация регулярным выражением по формуле
заголовка решения: «№ N. — YYYY года <месяц> D-го дня». Каждая запись хранит смещения
в исходном тексте; записи с аномалиями (нет номера, разрыв нумерации, подозрительно
короткий текст) помечены флагом OCR и требуют сверки с изданием. Орфография не
модернизирована; поиск нормализует ѣ→е, і→и, ѳ→ф и конечный ъ, поэтому работает
запрос в современной орфографии.

## Деплой
Любой статический хостинг; для GitHub Pages — содержимое папки в корень репозитория
(или в /docs) и включить Pages. Данные подключаются через <script>, поэтому сайт
работает и просто с диска: достаточно открыть index.html двойным кликом,
папка data должна лежать рядом.

## Пайплайн (воспроизводимо)
1. `pandoc -t plain --wrap=none <том>.docx -o txt/<том>.txt`
2. `python3 fix_ocr.py` — исправление OCR (txt -> txt_fixed + журнал)
3. `python3 parse.py` — сегментация на решения (см. флаги: no_number, seq_gap, short_text)
4. `python3 enrich.py` — теги:
   темы (регулярные выражения по рубрике, при пустой рубрике — по постановочной
   части с пометой topic_from_body), губернии (газетир, форма «…ской губ.»),
   уставы (формулы цитирования), повод, участники присутствия,
   сословия/статусы фигурантов (словарь по рубрике), вид деяния (словарь по
   рубрике и постановочной части), исход дела (резолютивная формула
   «Правительствующій Сенатъ опредѣляетъ: …» — отмена, оставлено без
   последствий, разъяснение, предписание, указ, сообщение ведением и др.;
   у ~37% решений окончание повреждено OCR или формула нетиповая — без тега),
   инстанции (окружной суд, палата, мировой съезд и др.).

## Исправление OCR-искажений (fix_ocr.py)
Орфография оригинала (ѣ, і, ѳ, ъ) сохранена. Исправляются только искажения OCR:
Ступень 1 (правила): латинские и цифровые гомоглифы внутри кириллических слов,
мусорные символы внутри слов, мягкие переносы, склейка переносов и OCR-разрядки.
Ступень 2 (эвристика): редкое слово (частота <=2 в корпусе) заменяется словом из
частотного словаря самого корпуса на расстоянии редактирования 1, если кандидат
единственный и минимум в 20 раз частотнее; подстановки ограничены матрицей
OCR-путаниц (и/н, е/с, и/й, п/н и т.п.), грамматические пары (а/о, конечные
буквы) исключены. Ступень 2 допускает единичные ложные исправления — полный
журнал замен: data/corrections.tsv (1385 замен, 1345 пар).

## Перемешанные колонки: решено геометрически (extract_pdf.py)
Тома набраны в две колонки; docx-OCR склеил их построчно. Статистическое
расплетение (deinterleave.py, эксперимент) качества не дало. Работает
геометрия: текстовый слой ABBYY-PDF хранит координаты слов. Алгоритм:
жёлоб страницы (пустая полоса или голосование межсловных просветов) ->
EM-уточнение по реальным краям колонок -> слова раздаются по колонкам ->
строки кластеризуются ВНУТРИ колонки -> порядок чтения L, затем R;
колонтитулы (повторяющиеся шапки) отбрасываются. Валидация на томе 1879:
межколоночных химер вдвое меньше (1431 -> 762), связный текст, решений
53 вместо 54 у docx-пути при большем числе слов (80.9 тыс. против 74.7).
Прогон: `python3 extract_pdf.py <том>.pdf txt/<том>.txt`, далее обычный
пайплайн. Том 1879 уже извлечён из PDF; остальные ждут своих PDF.
