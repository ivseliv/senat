# Исправление смыслового поиска, 15 октября 2026

Область: 384 решения, 2152 пассажа из четырёх томов 1896, 1897, 1904 и 1905.
Сравниваются одни и те же тексты, индексы, справочник и неизменённые эталоны.
Исходная версия ядра: коммит `b246af6`, Git blob
`576d78b7abb667ad7c1a9af00f6009b2e931faf7`.

## Дефект и исправление

Разбор запроса передавал в поиск уже усечённую основу неизвестного слова.
Поиск повторно вызывал стеммер, например «нотариуса → нотариу → нотари»,
тогда как слова индекса обрабатываются один раз. Теперь сохраняется
нормализованное слово, а основа служит только для сопоставления псевдонимов.
Возвращаемые совпадения содержат слово, пригодное для однократной подсветки.
Повторы одного понятия/псевдонима/слова считаются одной группой.

В основном наборе 26 положительных и 4 отрицательных запроса; все 4

Порог контроля 0,65 recall@5 / 0,55 MRR сохранён. Полные результаты:
[основные](metrics.json), [1905](metrics-1905.json),
[30 дополнительных](metrics-independent.json),
[те же с частичными совпадениями](metrics-independent-partial.json).

Частичный режим предложен в 10 из 30 случаев. Эти дополнительные выдачи
не являются автоматическими ответами на полный вопрос: без нажатия кнопки
пользователь видит пустую выдачу и предложение уточнить поиск.
Пример «ответственность нотариуса за убытки» теперь первым находит 1897 №41
по всему запросу. Для «забытые вещи в поезде» частичный режим первым находит
1897 №16, с. 71–72, и отмечает отсутствие слова «поезде»; два следующих
фрагмента про железнодорожный пожар отмечают отсутствие «забытые».
Это показывает ограничение точности: рост recall не означает установленного
precision. Другие новые результаты не объявляются юридически релевантными
только на основании совпадения слов или старого ИИ-пояснения.

## Правила частичного режима

- Не меньше трёх различных групп; совпасть должны все, кроме одной.
- Все распознанные понятия справочника и числовые условия обязательны.
- Отрицание, кавычки, плюс или минус перед словом отключают ослабление.
- Полные результаты любого тома подавляют частичные всего корпуса.
- Пропущенное слово видно в каждой карточке и при открытии решения.
- Режим, исходный запрос и смещения сохраняются в прямой ссылке.

Это контролируемое уточнение навигации. Обычный смысловой поиск по-прежнему
не интерпретирует отрицание и операторы как юридические условия вопроса.

## Проверки и воспроизведение

```sh
python3 lex/build.py --single
python3 lex/test_parity.py
python3 lex/test_build.py
# В main OCR-листов нет. Для проверки происхождения нужен текстовый snapshot scans:
LEX_OCR_ROOT=/путь/к/snapshot/ocr python3 lex/test_concept.py
node lex/eval/search-quality.js
node lex/eval/run.js --fail-on-regression
node lex/eval/run.js --years 1905 --fail-on-regression
node lex/eval/run.js --suite eval/queries-independent.json
node lex/eval/run.js --suite eval/queries-independent.json --partial
node lex/eval/run.js --partial --fail-on-regression
python3 -m http.server 8770 --bind 127.0.0.1 -d lex
# В другом терминале с установленными Playwright/Chromium:
node lex/eval/search-quality-browser.js
```

`--output-dir` у оценщика сохраняет отчёты отдельно, не перезаписывая текущие.
Браузер проверяет все четыре тома, старую орфографию, подсветку, частичный режим,
скан и полную страницу, прямую ссылку/возврат, телефон, тёмную тему, офлайн HTML
и ошибки консоли. `LEX_TEST_URL`, `LEX_CHROMIUM` и `NODE_PATH` задают среду;
для компактной копии без растров `LEX_TEST_SCAN_URL` может указывать на
`https://ivseliv.github.io/senat/lex/` — проверяются настоящие опубликованные
изображения. В публичной проверке переопределение адреса сканов не требуется.

Дополнительные инженерные проверки защищают числа, повторы, отрицания,
кавычки, минус-слова, обязательные понятия и преимущество полных совпадений
в другом томе. Они не заменяют независимую юридическую оценку. Набор из 30
запросов уже раскрыт при диагностике; для следующей честной отложенной оценки
нужна новая выборка. Платные сервисы и LFS не использовались.
