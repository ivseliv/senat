# Static API v1

Публичная точка входа: <https://ivseliv.github.io/senat/lex/api/v1/manifest.json>.
Это **статический API**: GitHub Pages отдаёт готовые JSON-файлы по `GET` и
`HEAD`; ключ, учётная запись, платный сервис и серверная база данных не нужны.
Полная HTML-документация доступна по адресу
<https://ivseliv.github.io/senat/lex/api/>.

## С чего начать

Всегда сначала загрузите `manifest.json`. В нём находятся версия контракта,
`data_revision`, покрытие, размеры, SHA-256 и канонические URL файлов. Клиенту
не следует жёстко зашивать перечень томов или имена фасетов.

```sh
curl -L https://ivseliv.github.io/senat/lex/api/v1/manifest.json
curl -L https://ivseliv.github.io/senat/lex/api/v1/decisions/1904-042.json
```

```python
from hashlib import sha256
from urllib.request import urlopen
import json

base = "https://ivseliv.github.io/senat/lex/api/v1/"
manifest = json.load(urlopen(base + "manifest.json"))
decision = json.load(urlopen(base + "decisions/1904-042.json"))["item"]
assert sha256(decision["text_original"].encode()).hexdigest() == decision["text_sha256"]
print(decision["headnote_original"])
```

```js
const base = 'https://ivseliv.github.io/senat/lex/api/v1/';
const response = await fetch(base + 'decisions/1904.json');
if (!response.ok) throw new Error(`HTTP ${response.status}`);
const {items} = await response.json();
console.log(items.filter(d => d.outcome));
```

Файлы сейчас отдаются с CORS-заголовком GitHub Pages, но приложение должно
проверять `response.ok`: это статический хостинг, а неизвестный ресурс вернёт
обычную HTML-страницу 404, не JSON-ошибку API.

## Ресурсы

| Ресурс | Назначение |
| --- | --- |
| `manifest.json` | точка входа, состав снимка, SHA-256 и размеры каждого файла |
| `corpus.json`, `volumes.json` | годы, департаменты, полнота и ограничения корпуса |
| `decisions/index.json` | компактный указатель всех решений |
| `decisions/{year}.json` | полные записи решений одного года |
| `decisions/{decision_id}.json` | одно решение по постоянному ID, например `1904-042` |
| `passages/{year}.json` | пассажи поиска, точный текст и пояснения одного года |
| `participants/{year}.json` | строки печатного указателя одного года |
| `scans/{year}.json` | связи пассажей с изображениями страниц и координатами |
| `statutes/index.json`, `statutes/{act_id}.json` | упоминания исторических норм; `act_id` берётся из индекса |
| `legislation/unresolved.json`, `legislation/attribution.json` | остаток без установленного акта и покрытие сверки |
| `legislation/acts.json`, `legislation/citations/{act_id}.json` | названия актов и буквальные контексты ссылок |
| `legislation/historical-references.json` | сохранённые записи предыдущих версий, исключённые из текущих подсчётов |
| `facets.json`, `indexes/...` | материализованные фильтры по годам, темам, исходам, процедуре, нормам, участникам, должностным лицам и подборкам |
| `analytics.json`, `glossary.json` | данные аналитики и словарь понятийного поиска |
| `editorial/analyses.json`, `editorial/guides.json` | редакционные разборы и тематические подборки |
| `editorial/analysis-search.json` | разделы разборов с видами, пояснениями и точными цитатами для клиентского поиска |
| `bulk.json` | совместимые полные JSON/CSV-выгрузки из `lex/export/` |
| `openapi.json`, `schema.json`, `terms.json` | контракт, JSON Schema и условия использования |

Большие ресурсы намеренно разделены по годам: самый большой том содержит лишь
часть корпуса, поэтому для обычной работы не нужно скачивать все тексты.
Параметры URL вроде `?year=1904`, `?q=завещание` или `?page=2` **не
выполняются на сервере**. Для одного условия берите готовый файл из `indexes/`;
для нескольких пересекайте массивы `decision_ids` у себя. Полнотекстовый и
понятийный поиск воспроизводятся на стороне клиента по пассажам и словарю.

## Контракт данных

Контракт **1.7.0** объединяет темы сайта, API и экспорта. `topic_ids`
содержит постоянные ID из `editorial/topics.json`, `topics` — их названия.
Прежние автоматически извлечённые темы сохранены отдельно в `automatic_topics`.
Старые URL тематических фасетов работают как псевдонимы редакционных тем;
их состав мог измениться, поэтому сверяйте `data_revision`.

У решений и томов добавлен `volume_id`; в `volumes.json` также есть
`department_id`, `edition` и `decision_id_prefix`. ID существующих решений
и их прямые ссылки не изменены. Пока сборка по годам не поддерживает два
публикуемых тома одного года: приём новых PDF блокирует такую коллизию до
миграции всех индексов. Наличие реестра само по себе эту миграцию не заменяет.

`editorial/analysis-search.json` содержит 2 688 разделов всех 384 разборов.
`kind` различает вопрос, доводы стороны, предшествующее рассмотрение,
рассуждение и постановление Сената, редакционные пределы вывода. `speaker`
воспроизводит атрибуцию подготовленного разбора; он не превращает современное
пояснение в цитату Сената. Источники находятся в `quotes` и `evidence`.
Сравнительные подборки расширены до 9, с 20 различными делами.

OCR-подстановки и нечёткие совпадения выполняются только клиентским
поиском по производным индексам. Они не меняют `text_original`, цитаты,
SHA-256 или координаты сканов. API не предоставляет серверную строку поиска.

В версии **1.1.0** добавлены `precedents/{year}.json` и поле `precedents`
в решениях. Это упоминания прежних решений с буквальной цитатой, контекстом,
SHA-256 исходного текста и прямой ссылкой на место упоминания. Тождество
устанавливается по **department + year + number**. Только `status=linked`
даёт `target_id` и `target_url`. Остальные статусы: `department_unknown`,
`not_in_corpus`, `ambiguous_target`; при них оба целевых поля равны `null`.
Поле `year` такой записи относится к цитируемому тому; `source_year` — к
тому-источнику. `source_url` открывает цитату, `target_url` — прежнее решение.

Прежнее поле `cites` сохранено как устаревшие пары год/номер, без учреждения
и с ограничениями старого извлечения. **По нему нельзя создавать переходы
или устанавливать тождество решений.** В аналитике старое `cited` сохранено
без индексов-переходов; используйте `cited_decisions` и `precedent_counts`.
Ссылки без департамента не объединяются в рейтинг тождественных решений.
Само упоминание в решении не означает, что Сенат принял процитированный довод.

Все JSON-файлы используют UTF-8. Большинство наборов обёрнуты в объект с
полями `api_version`, `contract_version`, `data_revision`, `resource`, `count`
и `items`; эндпоинт одного решения использует `item`.

- `decision_id` имеет вид `YYYY-NNN` и является постоянным ключом решения
  текущего корпуса. `year` — год тома, а не всегда календарная дата решения.
  Если одну дату нельзя честно выразить в ISO, используется `date_label`.
- `passage_id` содержит границы текста. `start` и `end` — полуоткрытый
  диапазон Unicode-кодовых точек `[start,end)` в `text_original`, а не
  байтовые или UTF-16-смещения. Он может измениться при исправлении OCR;
  сохраняйте `data_revision` и `sha256` пассажа.
- `box=[x0,y0,x1,y1]` — доли ширины и высоты страницы от её левого верхнего
  угла. Если `box` отсутствует, точное место не подтверждено: используйте
  `full_page_url`, а не пытайтесь восстановить рамку.
- `participant_id` обозначает строку печатного указателя. Это не
  нормализованный человек, организация или процессуальная роль.
- Пустые скаляры представлены `null`, списки — `[]`, словари — `{}`.

`manifest.json` содержит SHA-256 и размер каждого API-файла. Если
`data_revision` поменялся, сопоставляйте запись с её новым `sha256` и не
смешивайте данные разных снимков.

## Степень достоверности

Контракт **1.6.0** добавляет `legislation/historical-references.json`
(`HistoricalLegislationReference`) и полную JSON/CSV-выгрузку
`legislation-historical-references`. Они сохраняют ссылки, исчезнувшие из
активного указателя после уточнения акта: прежний `id`, буквальные места,
SHA источников, основания и отдельную пометку `historical_note`. Прежний
`verification_status` описывает сохранённую запись, а не её актуальность.
Поле `current_references` перечисляет текущие записи того же решения с тем
же обозначением статьи: `id`, `code`, `article`, абсолютный `passage_url`
(или `null`). Список может быть пустым или содержать несколько записей;
он не устанавливает единственного преемника старой ссылки. JSON и CSV
сохраняют этот список; в CSV он записан JSON-массивом в одной ячейке.
Для текущих привязок используйте `legislation/citations/{act_id}.json` и
`legislation/unresolved.json`. История не включается в текущие ссылки,
`statutes`, фасеты и их счётчики; отдельный
`legislation_historical_references` считает только сохранённые записи.
Пустая история представлена `count=0` и `items=[]`. Старые пути API сохранены.

Контракт **1.5.0** добавляет `legislation/unresolved.json` и
`legislation/attribution.json`. В цитатах законодательства `verification_status`
равен `context_verified`, `legacy_unverified` или `act_unknown`. Это статус
привязки акта; правильность номера OCR и исторической редакции им не
удостоверяется. `field=text|headnote` задаёт поле для Unicode-смещений;
`source_sha256` и `headnote_sha256` закрепляют оба источника. `evidence`
сохраняет прямые/повторные цитаты и строки печатного указателя; `occurrences`
сохраняет проверенные места. Относительные `path` и `scans[].full` разрешаются
от корня `lex/`. Дополнительная `role=act_identity` поясняет идентичность акта.
`source_warning` и `attribution_note`, если есть, сохраняют ограничения.
Прежние URL фасетов сохраняются; опустевший после корректуры фасет имеет
`count=0`, пустые `decision_ids` и `status=no_current_matches`.
Счётчик `legislation_unresolved` считает пары «решение + обозначение статьи»,
а не физические упоминания. [Метод](LAW_ATTRIBUTION.md).


Контракт **1.4.0** добавляет `editorial/topics.json` (`TopicCatalog`) —
редакционный каталог всех решений с современными названиями, описаниями,
SHA полных текстов и цитатами каждого тематического включения. Индексы
`indexes/catalog-topic/<id>.json` и группа `catalog-topic` в `facets.json`
содержат точные наборы по ID тем. При выпуске 1.4.0 `topic` ещё содержал
автоматические метки; с 1.7.0 это тот же редакционный каталог. `guide`
сохраняет отдельные подборки.
Новые счётчики покрытия: `catalog_topics`, `catalog_decisions`,
`catalog_classified`, `catalog_memberships`. Одно дело может иметь несколько
включений. Полнота учёта дел не означает полноты всех возможных правовых тем.
[Метод и ограничения](TOPIC_CATALOG.md).

В контракте **1.3.0** ресурс `editorial/guides.json` сохраняет прежние темы и
списки `groups`, а также содержит `comparison` с выбранными делами `cases`,
их SHA-256, разделами и сопоставлениями `comparisons`. Каждый тезис имеет
`evidence` с ID решения, буквальной цитатой, смещениями и всеми страницами.
`editorial_note`, если есть, — отдельное редакционное примечание, не часть
цитаты. Определения `GuideComparison` и `EditorialEvidence` есть в схеме;
относительные `scans[].full` разрешаются относительно корня `lex/`.
Счётчики `guide_comparisons` и `guide_comparison_decisions` показывают
покрытие (при выпуске 1.3.0 — 3 сравнения, 8 дел). Фильтры `guide` объединяют старые списки с
выбранными делами сравнений. [Метод и ограничения](COMPARATIVE_GUIDES.md).

В контракте **1.2.0** у пассажей добавлено `source_warning` (`null` или строка).
Непустое значение отмечает обнаруженное смешение колонок, соседних решений
или обрыв текста. Такой пассаж доступен в оригинале, но его пояснение
не включено в обогащённый поисковый индекс. Предупреждение сохраняется и в CSV.
Редакционные разборы используют внутреннюю схему 2: полный текст цитаты,
закреплённый SHA решения и список всех страниц именно этой цитаты.

Текст воспроизводит OCR с дореформенной орфографией. Числа, даты, имена и
нормы следует проверять по изображению. Поля `topics`, `outcome`, `procedure`,
`participant_groups`, `statutes` и `ai_*` сформированы автоматически или
редакционно и не заменяют историческое исследование либо юридическое
заключение. `ai_summary` и `ai_concepts` — пояснения к буквальной цитате, не
первичный источник и не вывод о действующем праве. Указатель законодательства
не устанавливает редакцию статьи на дату решения.

## Совместимость, цитирование и права

В пределах `/api/v1/` существующие поля и файлы не удаляются и не меняют тип;
допускаются только добавочные поля и новые файлы. Несовместимая схема появится
в новом пути, например `/api/v2/`. Для воспроизводимого исследования указывайте
URL, `data_revision`, SHA-256 использованного файла и дату обращения:

> *Решения Правительствующего Сената*, Static API v1, data_revision `…`, URL
> ресурса, дата обращения.

Лицензия на тексты, OCR, метаданные и изображения в репозитории пока не
заявлена. Публикация API сама по себе не даёт права на повторное
распространение или коммерческое использование; перед этим нужно отдельно
проверить права на каждый вид материала.

## Обновление

API строится локально только из проверенных `lex/data/` и `lex/export/`:

```sh
python3 lex/build.py --single
python3 lex/test_export.py
python3 lex/test_api.py
```

При обновлении корпуса генератор меняет `data_revision`, пересчитывает файлы,
суммы и материализованные индексы. PDF, временные OCR-файлы и рабочие каталоги
в API не включаются.


После восстановления колонок 1896 изменились SHA30 решений и границы ряда пассажей. Новые координатные URL таких решений имеют параметр `v=1896-restored-20261019`; старый диапазон без подтверждения версии не выделяется. Используйте текущий URL ресурса, `data_revision` и SHA. См. [протокол реставрации](eval/restoration-search-2026-10.md).
