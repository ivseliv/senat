# Подготовка нового PDF и сохранность источников

`intake.py` проверяет уже локальный PDF и создаёт возобновляемый отчёт. Он не
запускает OCR или модель, не скачивает LFS, не копирует PDF и не изменяет
`lex/data/`, реестр или опубликованные изображения. Наличие текстового слоя
не означает, что правильно распознаны слова, порядок колонок и границы дел.

## Проверка PDF

Нужны локальные `pdfinfo` и `pdftotext` из Poppler. Сначала можно проверить
первые 50 страниц, затем продолжить в той же папке:

```sh
python3 lex/intake.py /полный/путь/к/тому.pdf \
  --out work/intake/senat-civil-1898-first \
  --volume-id senat-civil-1898-first --year 1898 \
  --department-id civil --department 'Гражданский кассационный департамент' \
  --edition 'Название и выходные данные конкретного издания' --max-pages 50

# Та же команда, без --max-pages, с дополнительным --resume.
```

В папке появятся `manifest.json` и `report.md`. Манифест содержит SHA-256 и
размер PDF, идентичность издания, число PDF-страниц, сведения о шифровании,
проверенные страницы, длину и SHA извлечённого текста каждой страницы и
короткий образец. Полный текст и изображения не дублируются. Номера PDF-страниц
не выдаются за печатные номера.

По умолчанию проверяются все страницы пакетами по 25. `--batch-pages 1`
уменьшает пакет для сложного PDF; допустимо от 1 до 100. После каждого полного
пакета состояние записывается атомарно. `--resume` пропускает уже проверенные
страницы только при совпадении SHA всего PDF, параметров тома и формата
извлечения. Новый источник требует новой папки. Обычный запуск никогда не
заменяет существующую папку результата. При аварийном завершении процесса
может остаться `.intake.lock`: удалять его можно только после проверки, что
прежний процесс остановлен. Завершённый отчёт всегда содержит
`publication.approved=false` и `publication.ready=false`.

Проверка PDF может выявить отсутствие текста или техническую ошибку чтения.
Она не определяет автоматически полноту сборника и историческую редакцию
актов. Отсутствие букв U+FFFD также не доказывает качество OCR.

## Реестр томов и совместимость

`volume-registry.json` отделяет постоянный `volume_id` от года. Запись
содержит департамент (`department_id` и название), год, конкретное издание,
статус и префикс ID решений. У четырёх опубликованных томов добавлены новые
`volume_id`, но публичные ID `1896-001`, `1897-001`, `1904-001`, `1905-001`
и все прежние адреса сохранены. `volumes.apply_registry(meta)` возвращает
метаданные с идентичностью томов и проверяет уникальность каждого решения.

Существующие сборщики текста, пассажей, законодательства и сканов всё ещё
адресуют файлы по году. Поэтому два тома одного года пока **нельзя публиковать**.
Реестр и intake различают их по изданию и департаменту, но отчёт указывает
необходимость миграции, а сборка прекращается при коллизии вместо перезаписи.
Новый формат ID на основе `volume_id` зарезервирован и поддержан валидатором
подборки для решений из проверенных метаданных; это не заявление о готовности
всех маршрутов/API к публикации таких томов.

Переход к публикации остаётся отдельной работой:

1. Установить издание, департамент, комплектность и ожидаемую нумерацию.
2. Проверить текст, порядок колонок, границы решений и соответствие листам.
3. Подготовить карту сканов, обновить производные данные и проверить цитаты.
4. Сопоставить показатели качества с действующим корпусом, проверить старые
   ссылки и подборки. Для второго тома того же года сначала мигрировать все
   зависимые ключи и контракты.
5. Получить явное одобрение включения проверенного тома и публикации. Сам
   intake не меняет `status` в реестре и не выполняет эту операцию.

## Неизменяемые изображения

`build_scans.py` использует SHA PDF в имени страницы для обоих вариантов:
разворотов и экспорта с одним листом на PDF-страницу. ID кадра включает SHA PDF
и геометрию. Старые PNG из `work/<year>/` без подтверждённой связи с PDF не
используются. SHA вычисляется потоком, без чтения большого PDF целиком в память.

Новые изображения сначала готовятся в рабочем кеше. Опубликованные пути
добавляются без замены существующих файлов; попытка записать иные байты по
тому же URL останавливается. Предыдущий манифест сохраняется в
`data/scan-history/<год>/<SHA манифеста>.json`, текущий переключается после
подготовки набора. Старые WebP не удаляются: они нужны ранее сохранённым
подборкам, HTML/Markdown и API-выгрузкам. Это увеличивает объём хранения;
автоматической очистки исторических источников нет. Уже удалённые прежними
версиями файлы этот механизм не восстанавливает.

## Подборки после исправления OCR

Обычные v1-подборки принимаются без миграции ID и заметок. Устаревшая цитата
больше не отменяет весь импорт. Сохраняются её оригинальный текст, SHA,
смещения, страницы, URL сканов и заметка; актуальность хранится отдельно в
необязательном `verification` со статусом `current`, `archived`, `missing`
или `unverified`. Статус из импортированного файла не считается проверкой:
интерфейс сверяет источник заново. Повреждённая схема и посторонние URL
по-прежнему отклоняются до изменения подборки.

Кнопка «Проверить актуальность» проверяет текущий источник. Если прежняя
цитата встречается в нём ровно один раз, отдельная кнопка позволяет сохранить
новую проверенную цитату с текущими координатами и страницами. Старый снимок
остаётся рядом. При нескольких совпадениях или изменившихся словах
перепривязка не угадывается. Проверка цитаты удостоверяет совпадение с OCR,
а не историческую достоверность текста или редакции нормы.

```sh
PYTHONDONTWRITEBYTECODE=1 python3 lex/test_intake.py
node lex/eval/reader-core.js
node lex/eval/reader-archive-browser.js
```

Последняя проверка требует Playwright и Chromium, использует синтетический
текст и перехваченный localhost без обращения к внешней сети. В тестах
intake создаётся малый двухстраничный PDF; реальные тома не обрабатываются.
